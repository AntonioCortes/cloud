Registros y Semantic Versioning

Un Docker Registry es la infraestructura donde se alojan tus imágenes empaquetadas. Docker Hub es el registro público, pero en la empresa utilizarás registros privados (AWS ECR, Azure ACR, Google GCR o Harbor auto-alojado).

El Peligro de "latest"

La etiqueta `latest` es simplemente la que se aplica por defecto si no especificas ninguna. Nunca uses `latest` en producción. Si alguien sube una versión con un error crítico bajo la etiqueta `latest`, tus servidores la descargarán y romperán la app.

Utiliza Semantic Versioning (SemVer): `MAJOR.MINOR.PATCH` (ej. `v1.2.4`).

Autenticación y Push

Para subir imágenes a un registro privado corporativo, el flujo completo es:


# 1. Autenticarte en el registro corporativo usando un token seguro
docker login mipropioregistro.com:5000

# 2. Etiquetar (Tag) la imagen apuntando al FQDN del registro
docker tag mi-app:v1.2.4 mipropioregistro.com:5000/mi-equipo/mi-app:v1.2.4

# 3. Empujar la imagen (Push)
docker push mipropioregistro.com:5000/mi-equipo/mi-app:v1.2.4

Docker Content Trust (DCT)

Para máxima seguridad, los registros modernos soportan firma de imágenes. Si activas export DOCKER_CONTENT_TRUST=1, Docker verificará la firma criptográfica de la imagen antes de ejecutar el contenedor para asegurar que no ha sido alterada por un atacante.
