Creación de Imágenes y UnionFS

Una imagen de Docker no es un bloque sólido; es un conjunto de capas superpuestas montadas bajo un sistema de archivos especial llamado UnionFS (Union File System). Cada instrucción `RUN`, `COPY` o `ADD` en tu Dockerfile crea una nueva capa inmutable.

Entendiendo la Caché y las Capas

Docker compila las imágenes en orden secuencial. Si cambias el código fuente (capa 5), Docker debe reconstruir esa capa y todas las posteriores. Por tanto, la regla de oro es instalar dependencias pesadas antes de copiar el código fuente que cambia frecuentemente.

Multistage Builds (El secreto del experto)

En lenguajes compilados (como Go o Java), necesitas el compilador para generar el binario, pero no lo necesitas para ejecutarlo en producción. Los Multistage Builds te permiten crear contenedores minúsculos y seguros.


# ==========================================
# Etapa 1: Compilación (Pesada)
# ==========================================
FROM golang:1.20-alpine AS builder
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
# Copiamos el código y compilamos un binario estático
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o mi-api .

# ==========================================
# Etapa 2: Producción (Ultraligera y Segura)
# ==========================================
FROM scratch
# Solo copiamos el binario ya compilado de la etapa anterior
COPY --from=builder /app/mi-api /mi-api
ENTRYPOINT ["/mi-api"]
Ejemplo de Multistage Build. La imagen final partirá de "scratch" (vacía), ocupando apenas megabytes.
