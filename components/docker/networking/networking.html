Networking Interno y DNS

El stack de redes de Docker utiliza Network Namespaces y puentes virtuales (virtual bridges) de Linux (docker0) para enrutar tráfico. Conocer los drivers de red es crítico para microservicios.

El Driver Bridge y el DNS de Docker

La red `bridge` por defecto de Docker tiene un defecto enorme: no proporciona resolución DNS entre contenedores. Solo puedes comunicarte por la IP del contenedor (que cambia constantemente).

Si creas una Red Bridge Personalizada, Docker inyecta un servidor DNS interno en la IP 127.0.0.11 dentro de cada contenedor. Esto te permite hacer pings y conexiones HTTP utilizando el nombre del contenedor, lo que hace posible la orquestación real.


# Crear red con resolución DNS incorporada
docker network create net-backend

# Ahora 'api' y 'db' pueden hablar entre ellos usando sus nombres
docker run -d --name api --network net-backend mi-api
docker run -d --name db --network net-backend postgres

Drivers Avanzados: Host y Macvlan

  • Host: `docker run --network host`. El contenedor pierde su aislamiento de red y usa el mismo stack que el servidor. Se usa para aplicaciones de ultra-baja latencia donde el NAT de Docker añadiría milisegundos inaceptables.
  • Macvlan: Permite asignar una dirección MAC real al contenedor, haciéndolo parecer un dispositivo físico directamente conectado a la red de tu oficina o data center. Perfecto para migrar aplicaciones legacy que requieren IPs reales de la misma subred física.
