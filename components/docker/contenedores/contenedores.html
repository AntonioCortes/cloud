Dominando los Contenedores

Cualquiera puede ejecutar `docker run`, pero para llevar una aplicación a producción necesitas conocer a fondo cómo gestionar su ciclo de vida, inyectar configuraciones dinámicas y limitar sus recursos de hardware a través de cgroups.

Inyección Dinámica y Límites de Hardware

Imagina que quieres lanzar un contenedor de Redis, pero limitando su memoria RAM, inyectando variables dinámicas y asegurando que se reinicie si el sistema falla. Esto se logra combinando banderas críticas:


docker run -d \
  --name redis-cache \
  --restart unless-stopped \
  --memory="512m" \
  --cpus="0.5" \
  -e REDIS_PASS="secreto-seguro" \
  -p 127.0.0.1:6379:6379 \
  redis:7-alpine
Bandera (Flag) Explicación Experta
--restart unless-stopped Política de reinicio. Le dice al demonio que si el proceso muere por un error (o si el servidor se reinicia), vuelva a levantar el contenedor automáticamente.
--memory y --cpus Aplica restricciones directas a los cgroups del kernel. Evita que un memory leak en tu app mate todo el servidor.
-p 127.0.0.1:... Bind local. Evita exponer el puerto directamente a Internet (0.0.0.0), exponiéndolo solo a la interfaz local del host (localhost).

Inspección Profunda

Si un contenedor falla y `docker logs` no es suficiente, puedes entrar a su Namespace para depurarlo en vivo usando docker exec -it mi-contenedor sh, obteniendo una terminal directa al corazón del proceso aislado.
