Instalación y Configuración de Docker

Instalar Docker puede variar enormemente dependiendo del sistema operativo y del propósito de la máquina (un entorno de producción vs. tu ordenador personal para desarrollo). En esta guía detallada, exploraremos paso a paso cómo instalar y configurar Docker desde cero, culminando con la ejecución de tu primer contenedor: el clásico Hello World.

A nivel interno, Docker funciona con una arquitectura Cliente-Servidor. El cliente (lo que tú escribes en la terminal) se comunica con el demonio de Docker (el servidor que hace el trabajo pesado) normalmente a través de un socket UNIX (en Linux) o un named pipe (en Windows). Entender esto es fundamental para comprender los permisos y el funcionamiento de la herramienta.

1. Instalación en Linux

Linux es el ecosistema natural de Docker. Los contenedores comparten el núcleo (kernel) del sistema operativo anfitrión, lo que los hace increíblemente ligeros y rápidos. Podemos considerar esta instalación la forma más "pura" de usar Docker.

1.1. Para Ordenadores Personales (Entornos de Desarrollo)

Si usas Linux como tu sistema operativo de escritorio diario (por ejemplo, Ubuntu Desktop) y quieres empezar a desarrollar, la forma más sencilla y moderna es utilizar Docker Desktop para Linux. Esta herramienta incluye una interfaz gráfica (GUI) que facilita enormemente la gestión de contenedores, imágenes y volúmenes, además de incluir herramientas adicionales muy útiles como Docker Compose o un clúster de Kubernetes preconfigurado.

  1. Descarga el paquete .deb (para Ubuntu/Debian) o .rpm (para Fedora/RedHat) desde la página oficial de Docker.
  2. Instala el paquete utilizando el gestor de paquetes de tu distribución. Por ejemplo, en Ubuntu:
sudo apt-get update
sudo apt-get install ./docker-desktop-<version>-amd64.deb

Es importante saber que Docker Desktop en Linux ejecuta una máquina virtual ligera de fondo para proporcionar un entorno totalmente consistente, lo que significa que aísla los recursos del sistema principal de forma más estricta que la instalación nativa del Engine.

1.2. Para Entornos de Producción (Servidores Headless)

En un servidor en la nube (como una instancia EC2 en AWS, una VM en Azure o un VPS clásico) donde no hay interfaz gráfica (son entornos headless), queremos instalar únicamente el motor puro: Docker Engine. Queremos evitar la sobrecarga de una máquina virtual y usar la potencia bruta del sistema operativo del servidor.

La manera oficial y recomendada de instalar Docker Engine en Linux (el ejemplo asume Ubuntu/Debian) es mediante el repositorio oficial de Apt:

# 1. Actualizar el índice de paquetes e instalar dependencias base
sudo apt-get update
sudo apt-get install ca-certificates curl

# 2. Añadir la clave GPG oficial de Docker para verificar la autenticidad
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. Añadir el repositorio oficial a las fuentes de Apt
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. Instalar Docker Engine y sus plugins (como Compose)
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

Configuración Post-Instalación Crítica (Linux)

Por defecto, el demonio de Docker requiere privilegios de root para ejecutarse. Si intentas ejecutar el comando docker run sin usar sudo, obtendrás un error de "Permisos Denegados". Para evitar tener que escribir sudo cada vez y agilizar tu flujo de trabajo de forma segura:

# Crear el grupo docker (normalmente se crea en la instalación, pero por si acaso)
sudo groupadd docker

# Añadir tu usuario actual al grupo docker
sudo usermod -aG docker $USER

# Aplica los cambios de sesión inmediatamente (o simplemente cierra sesión y vuelve a entrar)
newgrp docker
Nota de seguridad: Cualquier usuario que pertenezca al grupo 'docker' tiene privilegios equivalentes a 'root' en la máquina anfitriona. Esto es ideal para desarrollo local, pero requiere precaución extrema en servidores compartidos.

2. Instalación en Windows

A diferencia de Linux, el núcleo (kernel) de Windows es completamente diferente. Dado que la inmensa mayoría de los contenedores están basados en Linux, para correrlos en Windows necesitamos una capa de virtualización que traduzca o ejecute un núcleo de Linux.

2.1. Para Ordenadores Personales (Entornos de Desarrollo)

La herramienta indiscutible en este escenario es Docker Desktop para Windows. Históricamente, utilizaba una máquina virtual pesada tradicional con Hyper-V, pero hoy en día la recomendación y estándar de la industria es utilizar WSL 2 (Windows Subsystem for Linux 2).

Piensa en WSL 2 como un kernel de Linux real incrustado orgánicamente dentro de Windows, extremadamente rápido y que permite un acceso casi nativo a los archivos del sistema. Docker aprovecha este motor de fondo para ejecutar contenedores Linux a velocidades impresionantes.

  1. Prerrequisito vital: Instala WSL 2. Abre una terminal de PowerShell como Administrador y ejecuta: wsl --install. Tras esto, reinicia tu equipo.
  2. Descarga el instalador de Docker Desktop para Windows desde su web oficial (docs.docker.com).
  3. Ejecuta el instalador. Asegúrate de que la casilla que dice "Use WSL 2 instead of Hyper-V" esté marcada durante la instalación.
  4. Una vez instalado, abre la aplicación. Tendrás un icono de una ballena en la bandeja del sistema (abajo a la derecha) indicando que el motor está arrancando (en color verde cuando esté listo).

2.2. Para Entornos de Producción Windows

Aunque la mayoría de los servidores corren en Linux, existen entornos empresariales puramente Windows. En servidores de producción basados en Windows Server, no se instala Docker Desktop (ya que incluye componentes gráficos y restricciones de licencia para empresas grandes).

En su lugar, para ejecutar aplicaciones nativas de Windows Server en contenedores, se utiliza Mirantis Container Runtime (anteriormente conocido como Docker Engine Enterprise). Si solo necesitas el motor puro en un entorno de desarrollo dentro de Windows Server, se utiliza PowerShell para instalar el proveedor nativo, el cual permite aislar aplicaciones usando Windows Containers exclusivamente (no Linux).

3. Configuración Avanzada: El archivo daemon.json

Tanto en Linux como en Windows, el "cerebro" de las operaciones (el demonio de Docker) puede configurarse de manera sumamente precisa utilizando un archivo de texto en formato JSON llamado daemon.json.

  • En Linux, se ubica en: /etc/docker/daemon.json
  • En Windows (con Docker Desktop), puedes acceder a él directamente desde los ajustes (Settings > Docker Engine) en la interfaz gráfica.

Una configuración extremadamente común (y recomendada en producción) es establecer políticas de rotación para los logs. Si no lo haces, un contenedor con errores que imprima texto constantemente puede agotar todo el espacio de tu disco duro y tirar el servidor abajo:

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
Ejemplo de configuración: Limita los logs a un máximo de 3 archivos de 10 Megabytes por contenedor, garantizando que el almacenamiento nunca se llene.

4. Tu Primer Contenedor: Ejecutando "Hello World"

Con Docker ya instalado y configurado correctamente, es el momento de poner a prueba la instalación. El rito de iniciación universal en Docker es descargar y ejecutar la imagen oficial llamada hello-world.

Abre tu terminal preferida (Bash, Zsh, o PowerShell) y ejecuta el siguiente comando exacto:

docker run hello-world

¿Qué magia acaba de suceder bajo el capó?

  1. El Cliente Docker (la herramienta de la línea de comandos a la que llamaste escribiendo docker) contactó con el Demonio Docker en segundo plano.
  2. El demonio buscó la imagen "hello-world" en tu disco duro local (tu caché).
  3. Al no encontrarla porque es una instalación nueva, el demonio salió a internet para contactar con Docker Hub (el registro público oficial) y descargó la imagen.
  4. Una vez descargada, el demonio creó un nuevo contenedor basado en esa imagen.
  5. El contenedor se ejecutó, el programa interno emitió el mensaje de saludo en tu pantalla y luego el contenedor finalizó su ejecución instantáneamente, ya que esa era su única misión.

Si la salida en tu consola muestra un texto que comienza por "Hello from Docker! This message shows that your installation appears to be working correctly.", ¡enhorabuena! Tienes un entorno Docker completamente funcional y estás listo para adentrarte en el mundo de la contenedorización.
