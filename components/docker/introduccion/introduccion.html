Introducción a Docker

Para dominar Docker, primero debes olvidar el concepto de "Máquina Virtual" y entender qué hace exactamente el núcleo del sistema operativo Linux. Docker no emula hardware; utiliza características nativas del kernel de Linux para crear procesos completamente aislados que *creen* estar en su propia máquina.

La magia detrás del Telón: Namespaces y Cgroups

Un contenedor es simplemente un proceso en tu ordenador al que se le han aplicado dos tecnologías clave del kernel de Linux:

Tecnología del Kernel ¿Qué hace? (Aislamiento)
Namespaces Aísla lo que el proceso puede ver. Le da al contenedor su propio árbol de procesos (PID namespace), su propia red (NET namespace) y su propio sistema de archivos (MNT namespace).
Control Groups (cgroups) Aísla lo que el proceso puede usar. Limita la cantidad de CPU, Memoria RAM y ancho de banda de I/O de disco que el contenedor puede consumir, evitando que monopolice el sistema.

Arquitectura de Docker

Cuando ejecutas un comando de Docker, intervienen tres piezas fundamentales:

  • Docker Client: La CLI (`docker run`). Es un cliente ligero que envía peticiones HTTP REST.
  • Docker Daemon (dockerd): El servidor que escucha las peticiones de la API REST y gestiona los objetos (construye imágenes, arranca contenedores usando `containerd`).
  • Registry: El almacén en la nube donde residen las plantillas inmutables (Imágenes) listas para descargar.
