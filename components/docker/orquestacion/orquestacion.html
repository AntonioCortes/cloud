Orquestación Experta: Docker Swarm

Para alta disponibilidad y balanceo de carga entre múltiples servidores, pasamos de Compose a Swarm. Swarm transforma un grupo de servidores Docker en un único clúster virtual.

El Algoritmo Raft y el Quórum

Los nodos Manager mantienen el estado del clúster sincronizado a través del algoritmo de consenso Raft. Para que el clúster sobreviva a caídas, necesitas un número impar de Managers (generalmente 3 o 5) para mantener el Quórum (mayoría absoluta). Si pierdes el Quórum, el clúster no puede asignar nuevas tareas, aunque los contenedores actuales seguirán corriendo.

Redes Overlay y el Routing Mesh

Cuando tienes un servicio (ej. servidor web) replicado en 3 nodos distintos, ¿a qué IP debe atacar el balanceador de carga externo? Swarm resuelve esto con el Routing Mesh.

  • Swarm expone el puerto público en todos los nodos del clúster simultáneamente.
  • Si un cliente externo ataca al Nodo A (que no tiene el contenedor corriendo), el kernel de Linux en el Nodo A (usando IPVS) enruta mágicamente el tráfico a través de una red Overlay cifrada hasta el Nodo B que sí tiene el contenedor.

# Crear red cifrada entre diferentes servidores físicos
docker network create -d overlay --opt encrypted mi-red-global

# Desplegar servicio replicado y auto-balanceado
docker service create --name web --replicas 5 -p 80:80 --network mi-red-global nginx
