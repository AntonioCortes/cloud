Instalación y Configuración (Clúster Local y Producción)

Instalar Kubernetes no es como instalar un simple programa (como Word o un navegador). Kubernetes es un sistema distribuido complejo compuesto por múltiples nodos (servidores). Instalar un clúster de producción desde cero ("the hard way") implica configurar certificados TLS, red virtual (CNI), un almacén distribuido (etcd) y configurar los agentes (kubelet) y demonios manualmente.

Afortunadamente, para aprender y desarrollar, existen excelentes herramientas que encapsulan toda esa complejidad en nuestra propia máquina local.

1. La Herramienta Universal: kubectl

Antes de arrancar ningún clúster, necesitamos la herramienta con la que nos comunicaremos con él. Esta herramienta se llama kubectl (pronunciado kube-control o kube-c-t-l).

kubectl es el cliente de línea de comandos de Kubernetes. A través de él, enviamos los archivos YAML o comandos directos al plano de control (Control Plane) del clúster.

Instalación de kubectl (Linux)

Para descargar la última versión binaria y hacerla ejecutable:

# Descargar el binario
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"

# Dar permisos de ejecución
chmod +x ./kubectl

# Mover el binario al PATH del sistema
sudo mv ./kubectl /usr/local/bin/kubectl

# Verificar la instalación
kubectl version --client

2. Entorno de Desarrollo Local: Minikube

Si quieres probar K8s en tu PC, no vas a comprar 5 ordenadores para montar un clúster. Utilizaremos Minikube. Minikube levanta rápidamente un clúster de Kubernetes de un solo nodo (donde el Master y el Worker residen en la misma máquina virtual o contenedor) en tu ordenador local.

Nota: Existen otras alternativas muy populares como Kind (Kubernetes in Docker) o K3s (versión ultra ligera de K8s), pero Minikube es el estándar académico más adoptado.

Prerrequisitos

  • Tener instalado un hipervisor (VirtualBox, Hyper-V) o un gestor de contenedores (Docker). Utilizaremos Docker por ser más ligero.
  • Mínimo 2 CPUs y 2GB de memoria libre.

Instalación de Minikube (Linux)

# Descargar e instalar Minikube
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

Arrancando tu Clúster Local

Con Minikube y Docker instalados, iniciar tu clúster personal es tan sencillo como ejecutar:

# Iniciamos indicando que use Docker como motor interno
minikube start --driver=docker

Verás en pantalla cómo Minikube descarga una imagen, arranca el contenedor, genera los certificados de seguridad y configura automáticamente kubectl para que apunte a este nuevo clúster.

Verificando el clúster

Ejecuta tu primer comando contra el clúster:

kubectl get nodes

Deberías ver un nodo llamado `minikube` con el estatus `Ready`. ¡Felicidades! Ya tienes Kubernetes en tu máquina.

3. Entornos de Producción: Una visión general

Minikube es exclusivo para desarrollo local. Nunca debes usarlo en producción. Cuando se trata de montar K8s en un entorno real, la industria se divide en dos grandes enfoques:

A. Clústeres Gestionados (Cloud) - El Enfoque Moderno

Montar, asegurar y mantener el Control Plane (los nodos maestros) es sumamente difícil. Por ello, lo más común en las empresas es utilizar servicios gestionados donde el proveedor de nube te administra el Maestro, y tú solo gestionas (y pagas) por los nodos Trabajadores.

  • EKS (Elastic Kubernetes Service): El servicio de AWS.
  • GKE (Google Kubernetes Engine): El de Google Cloud (pioneros y el más avanzado).
  • AKS (Azure Kubernetes Service): La solución de Microsoft.

Con estos servicios, no instalas Kubernetes manualmente; haces unos cuantos clics en una interfaz o usas herramientas como Terraform, y en 10 minutos tienes un clúster de grado militar listo.

B. Clústeres Bare Metal o Auto-gestionados: kubeadm

Si tienes tus propios servidores físicos (Bare metal) y no usas la nube pública, debes montar K8s desde cero. La herramienta estándar para inicializar clústeres a nivel de producción es kubeadm.

El flujo básico (muy simplificado) con `kubeadm` requiere instalar primero Docker/containerd en todos los servidores y luego:

  1. Ejecutar kubeadm init en el servidor principal para arrancar el Máster. Esto genera un Token criptográfico de unión.
  2. Instalar y configurar un proveedor de red de pods (ej: Calico, Flannel).
  3. Ir a los otros servidores (Trabajadores) y ejecutar kubeadm join <IP-del-Master> --token <Token> para que se unan al clúster maestro de forma segura.

4. Tu Primer Despliegue en Minikube

A modo de "Hello World" en K8s, vamos a desplegar un servidor web simple (Nginx) y a exponerlo localmente.

# 1. Crear un despliegue llamado "hola-web" con la imagen de Nginx
kubectl create deployment hola-web --image=nginx

# 2. Comprobar que el Pod se ha creado
kubectl get pods

# 3. Exponer ese despliegue en un puerto local para poder verlo en nuestro navegador
kubectl expose deployment hola-web --type=NodePort --port=80

# 4. Magia de Minikube: Nos da una URL accesible para ver nuestro Nginx
minikube service hola-web

Si se abre el navegador con la pantalla de bienvenida de Nginx, tu clúster de Kubernetes está operando a la perfección y orquestando tu primer contenedor.
