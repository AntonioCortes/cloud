Integración Git: Multibranch Pipelines

Un Pipeline normal atado a un repositorio compila una sola rama (generalmente `main`). Pero en la vida real, un equipo de desarrollo trabaja en docenas de ramas (`feature/X`, `bugfix/Y`) y abriendo *Pull Requests*.

El poder del Multibranch Pipeline

Un experto no crea un Job en Jenkins por cada rama nueva. Crea un único Multibranch Pipeline. Jenkins escanea automáticamente todo tu repositorio de GitHub o GitLab. Por cada rama que contenga un archivo `Jenkinsfile`, Jenkins crea un Job subordinado automáticamente.

Funcionalidad Comportamiento Multibranch
Descubrimiento Detecta ramas nuevas y Pull Requests instantáneamente.
Limpieza (Orphaned Items) Cuando fusionas o borras una rama en Git, Jenkins elimina el Job temporal asociado para no ensuciar la interfaz.
Bloqueo de PRs Si el build de la rama falla, Jenkins reporta el estado (Check) a GitHub, bloqueando el botón de "Merge Pull Request".
Automatización a nivel organizacional

Seguridad de Webhooks

Cuando usas Webhooks para disparar Multibranch Pipelines, GitHub envía un Payload HTTP a Jenkins. Para evitar ataques de denegación de servicio (DDoS) o inyecciones, siempre configura un "Webhook Secret". Jenkins validará la firma criptográfica (HMAC) del Payload usando este secreto antes de procesarlo.
