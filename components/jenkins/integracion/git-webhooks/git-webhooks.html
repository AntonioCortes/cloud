Integración con Git y Webhooks

El poder de Jenkins reside en su capacidad para reaccionar a eventos. Si subes código a GitHub o GitLab, Jenkins debe enterarse y ejecutar automáticamente el Pipeline para asegurar que el nuevo código funciona.

Polling SCM vs Webhooks

Estrategia Descripción
Polling SCM (Malo) Jenkins le pregunta a GitHub cada minuto: "¿Hay cambios?". Desperdicia ancho de banda y recursos.
Webhooks (Recomendado) Jenkins espera dormido. GitHub le envía una petición HTTP en el momento exacto en que alguien hace git push.
Estrategias de disparadores (Triggers)

Definiendo el Trigger en el Pipeline

Puedes configurar esto en la interfaz web de Jenkins (en la configuración del Job apuntando al repositorio de Git) o declararlo en el código:


pipeline {
    agent any
    triggers {
        // Ejecuta el pipeline cada noche a la 1:00 AM usando sintaxis cron
        cron('H 1 * * *')
        // Si usas polling SCM (ejemplo cada 15 min):
        // pollSCM('H/15 * * * *')
    }
    stages {
        stage('Test') {
            steps {
                echo 'Testing triggered build...'
            }
        }
    }
}

Nota: Para los Webhooks, simplemente configuras la URL de Jenkins en GitHub (http://tu-jenkins/github-webhook/) y activas la casilla "GitHub hook trigger for GITScm polling" en tu Job de Jenkins.
