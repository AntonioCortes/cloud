Instalación Avanzada: DooD y JVM

Montar Jenkins en Docker es fácil, pero prepararlo para CI/CD real requiere conocimientos avanzados. Necesitas que Jenkins sea capaz de compilar contenedores Docker dentro de sus propios pipelines, y necesitas afinar la Máquina Virtual de Java (JVM).

Docker out of Docker (DooD) vs Docker in Docker (DinD)

Evita DinD (correr un demonio de Docker anidado dentro de Jenkins) por problemas de seguridad y rendimiento de archivos. La técnica experta es DooD: mapear el socket del host para que Jenkins utilice el demonio del servidor padre para crear contenedores hermanos.


# Lanzamiento experto de Jenkins
docker run -d \
  --name jenkins \
  --restart always \
  -p 8080:8080 \
  -p 50000:50000 \
  -v jenkins_data:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e JAVA_OPTS="-Xmx2048m -Xms512m -XX:+UseG1GC" \
  jenkins/jenkins:lts
Configuración Impacto
/var/run/docker.sock Mapeo del socket. Permite a los pipelines ejecutar docker build y docker run usando el Engine del anfitrión.
JAVA_OPTS Asignación estricta de memoria (Heap Size) y uso del Garbage Collector (G1GC) para evitar que Jenkins colapse con cientos de builds concurrentes.
