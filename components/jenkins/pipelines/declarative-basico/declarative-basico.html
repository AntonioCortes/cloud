Declarative Pipelines Básicos

Un Pipeline de Jenkins se escribe normalmente en un archivo llamado Jenkinsfile. Jenkins usa la sintaxis Declarativa, que es un formato muy legible y estructurado.

Anatomía de un Pipeline

Todo pipeline moderno se estructura en Stages (Fases) y Steps (Pasos).


pipeline {
    agent any // Indica que puede correr en cualquier nodo de Jenkins disponible

    stages {
        stage('Build') {
            steps {
                echo 'Compilando el código...'
                sh 'make build' // Ejecuta un comando en la shell de Linux
            }
        }
        
        stage('Test') {
            steps {
                echo 'Ejecutando pruebas unitarias...'
                sh 'make test'
            }
        }
        
        stage('Deploy') {
            steps {
                echo 'Desplegando la aplicación en producción!'
                sh './deploy.sh'
            }
        }
    }
}
El clásico ciclo Build-Test-Deploy en Groovy Declarativo

Bloques Importantes

  • pipeline { }: Es el bloque envolvente. Todo lo declarativo debe ir dentro.
  • agent: Define dónde (en qué máquina física o contenedor) se ejecutará este pipeline.
  • stages: Contenedor para múltiples fases del ciclo de vida. Las fases se ejecutan de forma secuencial por defecto.
  • steps: Son los comandos reales a ejecutar (como sh para bash, echo para imprimir en log, o plugins específicos).
