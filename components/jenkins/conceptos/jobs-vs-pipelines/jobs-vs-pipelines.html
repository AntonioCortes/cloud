El Cambio de Paradigma: Pipeline as Code

Para entender Jenkins a nivel experto, debes comprender la historia de la Integración Continua (CI). Antaño, los "Freestyle Jobs" gobernaban; eran interfaces web llenas de casillas donde el equipo de DevOps configuraba qué repositorios descargar y qué scripts ejecutar.

El problema del "ClickOps"

  • Síndrome del Servidor Mascota: Si alguien cambiaba accidentalmente una configuración vital en un Job de la interfaz web, el build se rompía y nadie sabía quién ni qué había tocado (sin auditoría).
  • Falta de portabilidad: Migrar 100 Jobs visuales a otro servidor de Jenkins requería exportar XMLs de forma manual y frágil.

La Revolución: Pipeline as Code

Jenkins introdujo los archivos Jenkinsfile. Este es el concepto de Infraestructura como Código (IaC) llevado al ciclo de vida del software.

Ventaja Explicación
Control de Versiones (Git) El Jenkinsfile vive dentro de tu repositorio (al lado de tu package.json o pom.xml). Cada cambio en el flujo de CI/CD queda registrado en un commit, con autor y fecha.
Revisiones de Código (PRs) Un desarrollador no puede cambiar la forma de compilar sin abrir un Pull Request que otro compañero debe aprobar. Esto asegura la calidad del proceso de build.
Sobrevivencia a Reinicios A diferencia de los Freestyle Jobs, los Pipelines modernos tienen un motor interno capaz de pausarse. Si Jenkins se reinicia abruptamente, el Pipeline se pausa y continúa donde lo dejó al volver a encenderse.
Por qué la industria entera migró a Pipeline as Code
